# GO 电机与气路接入联调临时文档

编写日期：2026-10-11。依据编写时的工程工作区，适用于“腕部已初步调好，GO 与气路尚未接入”的阶段。本文记录源码行为和建议测试流程，GO 增益、机械臂行程、气路接线与动作时间仍需实测填写；联调完成后将确认项并入正式文档。

## 1. 当前结论与接入顺序

**GO、气泵、阀板都已有软件接口，可以在现有机构任务中接入。当前配置还不足以直接启用 GO 或气路。** 腕部与 GO 使用不同通信总线，气路通过 GPIO 控制，现有框架不需要为它们另建控制任务；但三台电机共用机构状态与轨迹，阀板复用串口引脚，必须按下面的条件接入。

| 功能 | 已有能力 | 当前状态 | 接入前需要补齐 |
| --- | --- | --- | --- |
| 两台 M2006 腕部 | 差速换算、同步轨迹、位置/速度闭环、速度前馈、保持死区 | 已初步完成实机调试 | 保存基线；组合负载下复验 |
| GO 机械臂 | UART7 RS485 驱动、反馈、位置/速度给定、协议增益、机构标零与保护 | 驱动已运行；机构控制关闭 | 接线、ID、通信验证、外部传动比、行程、KP/KD |
| 气泵 | GPIO 开关、有效电平配置、停止时关闭 | 未分配 GPIO | 功率驱动、电源、空闲 GPIO、关闭初始电平 |
| 阀板/夹爪 | 三组可选 GPIO 接口、四路通道掩码、张开/夹紧/OFF 命令 | 掩码未配置 | 确认阀板协议、线圈通道、开合与停机的实际状态 |
| 自动取放流程 | 底层运动与气路命令可供调用 | 尚无流程控制 | 到位判据、建压/开合等待、动作超时、异常处理 |

建议按“保存腕部基线 → GO 只接通信 → GO 独立小动作 → GO 与腕部 → 气路独立 → 三者组合”推进。也可以先接气路，保持 `MECH_GO_CONTROL_ENABLE=0`；气路无需依赖 GO 在线。

当前基线：`MECH_CONTROL_ENABLE=1`、`MECH_GO_CONTROL_ENABLE=0`；GO 的 KP/KD、`arm_motor_ratio` 均为 0，`arm_range={0,0}`；泵端口为 NULL、引脚为 0，阀开/关/OFF 掩码均为 0。腕部增益、电流、死区和速度见 [参数配置](parameters.md)。本文不会把建议试验值当成已经确认的配置。

正常控制链：`Watch/未来上层 → command → 机构状态与轨迹 → output → GO/DJI/泵/阀适配 → 硬件`。反馈经驱动回到机构层，再检查掉线、GO 错误和角度越界。

GO 与 DJI 驱动由 TIM2 按 1 ms 调度，机构任务每 5 ms 更新一次。气路没有独立任务，随机构输出更新；阀板相同掩码重复下发会被驱动跳过。现有 Watch 命令足够完成手动联调，无需先写新的通信协议。

## 3. 与现有功能的关系及冲突点

### 3.1 总线资源

| 功能 | 当前资源 | 接入注意 |
| --- | --- | --- |
| M2006/C610 | FDCAN3，PF6 RX / PF7 TX，ID 1/2 | GO 不占用这个 CAN 总线 |
| GO | UART7，PE8 TX / PE7 RX，4 Mbps；PG1 控制 RS485 收发方向；ID 0 | 使用板载 RS485 对应端口；不要把电机 RS485 线直接接到 MCU 的 TTL TX/RX |
| VOFA | UART9，PD15 TX / PD14 RX，115200 | 与 GO 的 UART 和引脚分开，可同时观测 |
| 阀 BUS1 | PA9 数据 / PA10 时钟 | 与 USART1/模板 IMU 复用 |
| 阀 BUS2 | PD5 数据 / PD6 时钟 | 与 USART2 复用 |
| 阀 BUS3 | PD8 数据 / PD9 时钟 | 与 USART3 复用 |
| 气泵 | 待选 GPIO | 不能占用 CAN、UART、PG1、LED、蜂鸣器、调试接口或其他已分配资源 |

GO 与腕部、VOFA 没有直接引脚复用。泵阀电源启动造成的压降、地线噪声或电磁干扰，仍可能表现为电机掉线或 MCU 重启；这是需要接入后实测的电气问题，不能由总线分开推断为已经排除。

UART7 当前为 8N1，RX/TX 使用 DMA1 Stream2/3，RX 为 Circular；UART9 使用 DMA1 Stream4/5，没有直接 Stream 重叠。CubeMX 再生成时保留 GO 的 RX 环形 DMA、UART IDLE 接收、发送完成时切回接收的回调，以及 PG1 的方向控制。不要重新启动第二套 UART7 接收或在别的任务调用同一串口发送。实际 CPU/栈余量和反馈延迟仍需实机观察。

**阀板初始化有一处现存资源占用：** `main.c` 无条件执行 `Solenoid_Init(SOLENOID_BUS1)`，会在 USART1 初始化后将 PA9/PA10 改成推挽 GPIO并发送掩码 0。即使 `air_ready=false`、`MECH_CONTROL_ENABLE=0`，或后来选择 BUS2/3，BUS1 仍会被初始化。IMU 任务当前未启动，所以尚无活跃 IMU 收发冲突；将来启用 IMU，必须统一阀接口与 USART1 的资源分配。

接气路时应统一启动入口：由应用层按所选总线初始化，清理不需要的模板 BUS1 初始化，并同步 CubeMX 的复用配置。选定阀 BUS 后，取消或重映射对应 USART 的引脚复用，不启动该串口的收发模块；再生成后核对 main 中的初始化调用。这是后续接入改动项，本次文档编写没有修改启动代码。BUS2/3 被选作阀接口后，同样不能再同时作为原串口使用。

### 3.2 三台电机共用控制状态

- GO 关闭时，只要求左右 M2006 的反馈，`pose.arm_deg` 必须为 0；`measured.arm_deg=0` 是未受控标记。
- GO 启用后，标零、使能、停止都作用于三台电机。没有“机构命令只使能 GO、腕部保持失能”的单轴模式。
- 电机已使能时，任一受控电机超过 100 ms 无有效反馈、GO 错误或实测姿态越界，都会进入 FAULT，停止三台电机，并将气路置为泵关和阀 OFF。
- GO 已接入但 `MECH_GO_CONTROL_ENABLE=0` 时，GO 反馈丢失或错误不参与腕部故障判定。
- 一条姿态命令的三轴共用五次轨迹进度。GO 或腕部的合成位移需要更长时间时，整个动作一起延长；启用 GO 后腕部某些组合动作变慢属于这一规划机制。

数学映射中 GO 只影响机械臂轴，腕部的俯仰/旋转换算保持原样。`pitch_deg` 是相对机械臂的俯仰角，GO 转动时保持相同 `pitch_deg` 不等于夹爪在世界坐标中保持相同朝向。需要世界坐标姿态或末端位置控制时，还需上层运动学补偿；当前三轴接口不包含这层能力。

机械臂运动会改变重力方向、负载和惯性，气管也可能给腕部增加阻力。现有腕部参数是组合测试的基线，不能据此认定所有机械臂姿态下都已稳定。

### 3.3 气路独立给定，共享停止

`command=5` 不要求电机标零、使能或在线，只要求气路配置有效且机构不在 FAULT。因此可以在电机失能时独立测气路，也可以在 MOVING 时切换夹爪。普通使能、运动命令与轨迹结束不会自动关泵或改阀位，气路给定会一直保持到下一条气路命令、停止或主动故障。

电机未使能时要注意区别：UNCALIBRATED 不检查电机反馈；READY 中反馈丢失只使零位失效，气路给定仍保持。**目前没有“电机任何时候掉线都自动关气路”的规则。** 气路单测的结束和异常停机应显式发送停止命令。

Watch 只有一个 `command` 槽，没有队列。姿态与气路参数先分别填写，再逐条发送 4 和 5，等待前一条清零并检查结果；它们不是同一个原子动作，也没有自动到位后夹紧、定时建压或定时松开的功能。

GPIO 只能接泵的控制/功率驱动接口，不能直接给泵或阀线圈供电。感性负载保护、地线、线束与功率供电按实际模块设计确认。代码不知道所选 GPIO 是否与板上已有设备相连，也不知道 OFF 是否让夹爪泄压或松开。

GO 官方页面给出 GO-M8010-6 的 RS485 4 Mbps、减速比 6.33、工作电压 12～30 VDC、推荐 24 VDC；接线仍须按手中型号和板卡端口确认，产品额定值不能替代本机构的工作限制。[宇树 GO 官方参数](https://www.unitree.com/mobile/go1/motor/)

## 5. 联调共用操作与观测

在 Keil Watch 添加 `g_mechanism_debug`，开启 Periodic Window Update。所有 `command` 操作都遵守“先填完整参数 → 最后写 command → 等 command=0 → 检查 result”。

| command | 用途 | 说明 |
| --- | --- | --- |
| 1 | 全部停止、清除故障 | 三台受控电机失能，泵关，阀 OFF；正常停止保留零位，FAULT 后需重新标零 |
| 2 | 捕获机构零位 | 所有受控轴摆到约定零位，电机失能、配置有效、反馈在线 |
| 3 | 使能 | 从当前实测姿态开始保持；不自动回到零位 |
| 4 | 三轴姿态目标 | 填完 `pose.arm_deg/pitch_deg/roll_deg`；运动中返回 BUSY |
| 5 | 泵阀给定 | 填 `pump_on=0/1` 和 `claw=0/1/2`，分别为 OFF/OPEN/CLOSE |

| 观测项 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| `motion_ready` | 机构机械参数和增益通过配置检查 | 电机已经接好、在线或能承载 |
| `air_ready` | 气路宏配置与泵 GPIO 模式通过检查 | 泵阀已连接、压力正常、夹爪已经夹紧 |
| `go/left/right.online, age_ms` | 收到有效反馈且最近一帧未超过 100 ms | 到位精度、负载能力 |
| `go.error/temperature_c/torque_nm` | GO 返回的错误、温度和扭矩观测 | 软件已有自定义温度预警/扭矩限制 |
| `measured/setpoint/target` | 实测姿态、当前轨迹给定、最终目标 | 未标零或 FAULT 时的有效机构姿态 |
| `state=2 HOLDING` | 轨迹已结束或已进入保持 | 实物一定到位；须继续比较目标与反馈 |
| `output.pump_on/claw` | 软件当前要求的气路状态 | 实际泵运行、阀位或气缸到位反馈 |

`result=0` 只表示命令接受成功；之后仍需看 `state/fault`，故障可能在后续更新中出现。结果码：1 配置无效、2 状态不允许、3 未标零、4 反馈丢失、5 电机错误、6 目标无效、7 实测越界、8 运动忙。

GO 加入机构后，现有 VOFA 通道 0/3 可比较机械臂实测/轨迹给定；通道 1/4、2/5 比较腕部姿态，6～11 观察 DJI 速度和电流。GO 输出轴速度、扭矩和温度目前主要看 Watch；需要波形时调整注册通道，当前 12 路已全部占用，详见 [VOFA 调试](vofa_plus.md)。

停止会取消电机保持力矩。调试中须支撑机构和负载；暂停 CPU、单步或拔掉通信线不能当作正常停止。软件停止需要任务和驱动继续运行，硬件停机/供电处置按台架方案执行。

## 6. 阶段 A：保存基线与 GO 只接通信

1. 记录当前配置文件、固件版本、腕部零位定义和典型动作波形，保存可回退的腕部固件。更改接线前先发送 `command=1` 并支撑机构。
2. 保持 `MECH_CONTROL_ENABLE=1`、`MECH_GO_CONTROL_ENABLE=0`；先接 GO 电源与 RS485，不更改腕部增益。
3. 确认 GO ID=0，UART7/RS485 线序与供电正确。`USE_UNITREE=1` 已存在，驱动当前每 1 ms 尝试发送命令；GO 机构开关为 0 仍会周期发送失能模式，并接收反馈。
4. 观察 `g_mechanism_debug.go.online=true`、`age_ms` 持续刷新、`error=0`，温度与角度合理。在受支撑、允许手动转动的条件下，确认 GO 输出轴角度方向与变化连续。
5. 保持 `pose.arm_deg=0`，复测原有腕部动作。GO 在线与否此时不应成为腕部标零/使能条件；确认新增供电和线束没有引起 CAN 掉线、复位或波形异常。

通过条件：GO 有连续有效反馈，失能时不主动带动机构，原腕部动作能重复。只有 `data.correct=1` 不足以判断当前在线，该字段是锁存值；以机构记录的 `online/age_ms` 为准。

驱动的 `data.timeout` 未实际更新，坏帧计数也未有效发布到电机对象，不能用这两个字段判断通信已经可靠。需要深入查丢帧时，应增加可靠计数/日志或检查总线波形；UART/DMA 发送失败与直接模式掉线后的自动失能尚不能作为已验证能力。

## 7. 阶段 B：GO 独立低风险控制验证

此阶段用于确认驱动方向和协议增益，**不要求一定采用直接模式**。如果需要让 GO 单独动而保持 DJI 失能，现有机构模式没有单轴使能，需临时使用以下直接调试方式。若直接进入三电机机构模式，跳到阶段 C，并先保持腕部姿态不变。

1. 先在机构模式发送停止，支撑机械臂；将 `MECH_CONTROL_ENABLE=0`，重新编译下载。保持 `USE_UNITREE=1`，`DJmotor[0/1].Begin=false`，核实 DJI 确实失能。
2. 添加 `Unitree_motors[0]`。保持 `begin=true`、`enable=false`、`set_zero=false`，确认 GO 反馈在线。`begin=false` 会停发命令，不会发送失能指令；正常停止使用 `enable=false`。
3. 在失能状态，把 `cmd.position` 填为最新 `data.position`，先设 `cmd.speed=0`、`cmd.torque=0`，再填写低增益 KP/KD。模板初始化值为 KP/KD=0.02/0.02，这不是已经适配机械臂负载的确认值；具体起点由受支撑/卸载的小动作试验确定。
4. 最后写 `enable=true`，观察保持情况。再以当前目标为基准做小角度变化，确认方向和跟随；输出轴目标是 rad，1°约为 0.01745 rad，速度是输出轴 rad/s。不要直接把关节 deg 填到 `cmd.position`。
5. 停止写 `enable=false`，确认反馈模式和实际响应；结束后恢复 `MECH_CONTROL_ENABLE=1`，重新编译下载。

直接模式下，机构任务只观测，`g_mechanism_debug.command` 全部返回 `MECH_BAD_STATE`；机构的 100 ms 故障联停、行程限制、同步轨迹和气路命令不接管输出。不要在直接模式下依赖 `command=1` 停 GO。

机构接管时每 5 ms 更新 GO 的使能、速度和零扭矩前馈；GO 启用后还重写位置目标。GO 关闭时会强制失能，因此不能一边保留腕部机构接管，一边通过 Watch 写 GO `enable/cmd.position/torque` 来实现独立控制。

### GO 的两层零位与增益单位

`MOTOR_UNITREE_AUTO_SET_ZERO=0`，当前驱动默认不上电自动清零。驱动层 `set_zero=true` 会更改 `zero_offset`；机构 `command=2` 则记录驱动当前角度到机构自身零位，二者不同。正常联调保持驱动零位不变，只用机构标零；机构标零后再改驱动零位会破坏已有坐标关系。驱动 `set_zero` 没有强制失能检查，不应在使能时操作。

当前 `MECH_GO_KP/KD` 直接写入协议增益，再做定点编码；它们不是 DJI 的编码器计数位置 P/速度 PI，也不是已经转换到机械臂关节侧的刚度。官方 SDK 说明协议命令使用转子侧量，输出轴 KP/KD 换到转子侧需除以内部减速比的平方；本工程没有自动将所填 GO 增益按输出轴或外部机械传动换算，使用时要统一单位。[宇树官方 SDK 单位说明](https://github.com/unitreerobotics/unitree_actuator_sdk/blob/main/README.md)

**非零扭矩前馈暂列待核对项：** 驱动编码使用 `cmd.torque × 6.33 × 256`，解码使用 `raw / 256 × 6.33`。接口注释声称输出轴 Nm，但这两条换算不互逆；结合转子侧协议，非零输出轴扭矩的编码方向需要复核。当前机构每轮固定 `cmd.torque=0`，可以先验证位置/速度与增益，但不能据此认为非零扭矩前馈已经可用。接入重力补偿前应先完成协议对照和编码/解码测试。

`cmd.torque=0` 只表示显式扭矩前馈为零；启用 GO 后，位置/速度误差仍可通过 KP/KD 产生电机输出，不能将其理解为零总扭矩或已设置安全扭矩上限。

## 8. 阶段 C：GO 加入机构，与腕部联调

### 必填配置

| 配置 | 合法条件/含义 | 当前值与处理 |
| --- | --- | --- |
| `MECH_CONTROL_ENABLE` | 1，由机构统一控制 | 保持 1 |
| `MECH_GO_CONTROL_ENABLE` | 1，GO 参与机构与反馈保护 | 通信验证后再改为 1 |
| `arm_motor_ratio` | 有限且绝对值大于 1e-6；GO 减速器输出轴角 / 机械臂角，含正负方向 | 当前 0，必须填写实测值；不再乘内部 6.33 |
| `arm_range` | 有限，min < max，且包含 0° | 当前 `{0,0}` 无效，填实测关节安全行程 |
| `MECH_GO_KP` | 有限，0 < KP ≤ 25.599 | 当前 0 无效，填低增益试验确认值 |
| `MECH_GO_KD` | 有限，0 ≤ KD ≤ 25.599 | 填试验确认值；代码允许 0，不代表负载下适合 0 |
| `go_speed_limit_deg_s` | 有限且 > 0，GO 减速器输出轴规划速度上限 | 当前 30°/s；初调可暂时降低，记录改动 |
| `move_time_s` | 有限且 > 0，三轴共同最短时长 | 当前 1 s；初调可暂时延长，记录改动 |

测外部传动比时，在受支撑、反馈有效的条件下记录 GO 输出轴角变化和机械臂实测角变化，计算 `ΔGO输出轴角 / Δ机械臂角`，正反方向、多点检查，避免仅凭一次有间隙的小动作确定比例。如果希望机械臂速度不超过某个关节值，应按 `|arm_motor_ratio|` 换算成 GO 输出轴速度配置。

GO 速度上限目前用于计算轨迹时长，不是驱动总输出的硬限速，也不是扭矩/电流限幅。位置纠偏、增益和负载仍会影响实际速度。现有 DJI 的 3 A 限幅不会作用于 GO。

### 操作顺序

1. 填完配置并重新编译下载，保持气路关闭。确认 `arm_enabled=true`、`motion_ready=true`，GO/左右 DJI 都在线且 GO 无错误。只打开 GO 开关而不填参数会导致运动配置无效，连腕部的机构标零/使能也不可用。
2. 支撑三轴、摆到各自约定机械零位；写 2 标零，确认 `state=1 READY`，三轴实测零点符合定义。再写 3 使能，确认 `state=2 HOLDING`，无明显突跳。
3. 保持腕部当前目标，先让 `pose.arm_deg` 在零位附近做行程内的小动作，例如允许范围内 ±2°；每次填写全部三轴目标，最后写 4。比较 GO 输出轴与机械臂角度，确认正方向、比例和回零重复性。
4. GO 保持某一稳定姿态，复测纯俯仰、纯旋转与腕部组合动作。再换几个机械臂姿态，检查重力负载变化后是否仍平稳、保持误差是否可接受、M2006 是否长时间接近限流。
5. 最后做小幅 GO+俯仰、GO+旋转以及三轴同步动作，再逐步扩大到实际工作范围。比较实测与轨迹给定，不能只根据 HOLDING 判断通过。
6. 需要提高响应时，先确认低速负载下 GO 阻尼、保持和跟随稳定，再逐项提高规划速度/缩短共同最短时长。不同轴的 PID/协议增益分别调，不把 DJI 参数直接复制给 GO。

一条新姿态命令包含三个绝对关节目标，不是单轴增量命令。只改 arm 字段时，也要确认 pitch/roll 字段仍是希望保持的值，避免 Watch 中残留旧目标。

## 9. 阶段 D：气路配置与独立测试

### 配置合法性与通道映射

`MECH_CONTROL_ENABLE` 必须为 1；气路可以在 GO 开关为 0 时测试。`Mechanism_AirInit` 要求：泵端口非 NULL、引脚为 GPIO_PIN_0～15 中一个有效单引脚，已配置为推挽输出；有效电平为 SET 或 RESET；BUS 在 1～3；OPEN 与 CLOSE 掩码不同；所有掩码仅使用低四位；泵脚不与所选阀板的两根引脚重合。

代码只检查与所选阀 BUS 的重叠，未检查泵脚是否撞到 PG1、LED、蜂鸣器等资源。因此要人工核对完整 GPIO 分配。气路就绪是整体配置判据，单测泵或阀也需要合法的完整配置，不能用任意已配置输出脚冒充泵脚。

| 宏 | 填写规则 |
| --- | --- |
| `MECH_PUMP_GPIO_PORT / PIN` | 填实际功率驱动控制脚；在 CubeMX 配输出并以关闭电平启动 |
| `MECH_PUMP_ACTIVE_LEVEL` | 实测 SET 或 RESET 哪一个会让泵启动 |
| `MECH_VALVE_BUS` | 与实际阀板口一致，处理好对应 UART 复用 |
| `MECH_VALVE_OPEN_MASK` | 实物张开需要的线圈通道集合 |
| `MECH_VALVE_CLOSE_MASK` | 实物夹紧需要的线圈通道集合 |
| `MECH_VALVE_OFF_MASK` | 实物停机时要求的通道集合；与开合状态的机械后果一起记录 |

低四位分别对应通道 1～4：`0x01 / 0x02 / 0x04 / 0x08`。例如，只有确认通道 1 是张开线圈、通道 2 是夹紧线圈，且两者不能同时通电时，才可用 OPEN=`0x01`、CLOSE=`0x02`。这只是映射示例，不能直接作为当前机构接线。

代码不检查双线圈互斥、线圈通电时限或 OFF 的物理安全性，合法掩码也可能对实物产生错误动作。`claw=0` 只选择 OFF 掩码，不保证失电，也不保证松开。单线圈或双稳态阀应按实际动作方式定义掩码和停机方案。

### 启动状态必须先测

`Solenoid_Init` 总先发掩码 0，机构气路初始化随后才发配置的 OFF。若 OFF 不为 0，上电/初始化期间仍会短暂经过 0；main 中的 BUS1 初始化还会更早发送 0。接阀线圈和气源前，要确认这段启动行为可接受；若不可接受，先修改初始化，使整个启动过程使用一致的停机状态，再做实物动作测试。

泵初始化会写关闭电平，但软件不能控制 MCU 复位前或 GPIO 初始化前的电平。驱动输入的默认状态与上电波形需由硬件设计和实测确认。

### 独立测试步骤

1. 保持电机失能且机构有支撑，气压调到实物允许的试验条件。先确认驱动控制电平、线圈通道和断电状态；必要时分离功率/气源进行信号检查。
2. 更新 GPIO、阀总线和掩码，处理模板初始化与 UART 复用；重新编译下载。确认启动时泵关闭、阀处于已确认的停机状态，`air_ready=true`。
3. 先写 `pump_on=0, claw=0, command=5`，确认结果和实际状态；确认停止命令也产生相同的气路停机行为。
4. 在无夹持负载条件下分别检查张开与夹紧。每步先填泵/阀参数再发 5；若动作需要压力，按已确认气路顺序供气，并人工等待压力/动作稳定。记录开合时间、压力和泵工作时间。
5. 核对泵开关与阀位能分别改变；关泵后阀位是否保持、夹爪是否泄压，用实测确定。无异常后做重复开合，再引入轻负载。
6. 结束发送 `command=1`，确认泵关、阀 OFF，并按气路方案处理残余压力。不能只看到 `output.pump_on=false` 就认定已经泄压。

可用的气路命令组合如下，执行顺序由实际气路决定：

| `pump_on` | `claw` | 软件给定 |
| --- | --- | --- |
| 0 | 0 | 泵关，阀 OFF |
| 1 | 0 | 泵开，阀 OFF；只有气路允许此状态时才用 |
| 0 或 1 | 1 | 泵按给定，阀 OPEN |
| 0 或 1 | 2 | 泵按给定，阀 CLOSE |

每轮适配先写泵 GPIO，再写阀掩码，没有建压等待、阀切换等待、互斥间隔、压力闭环、泵 PWM 或自动停泵。泵为 1 就持续保持开启；需要“先选阀再开泵”时，应分两条命令并等待实际状态；需要更精确时序时，应在上层实现，不能用一条命令假定已经完成。

阀驱动只缓存最后发送的掩码，`Solenoid_Read` 不是硬件状态反馈。若阀板独立掉电/复位会丢失状态，MCU 缓存仍在，重复相同 command=5、周期输出，甚至相同 OFF 的停止命令都可能不重发。须在已确认安全的状态下按启动流程重新初始化/强制重发并确认实物状态，不通过任意切换掩码强迫重发；`result=0` 不能证明阀板已经恢复。目前没有阀板在线监测或自动恢复机制。

## 10. 阶段 E：三者组合联调

1. 先在无夹持负载情况下让 GO 和腕部保持，执行气路开合，观察电机角度/速度、电流、GO 在线状态及 MCU 是否复位。泵启动或阀切换时出现错误，先按供电/干扰与负载变化两个方向定位。
2. 保持气路某个固定状态，重复阶段 C 的单轴与组合动作，检查气管缠绕、拖拽和机构干涉。腕部旋转范围尤其要以实际管线余量复验。
3. 使用轻负载做“运动到取物姿态 → 确认实物到位 → 张开/夹紧 → 等待实测动作时间或反馈 → 移动 → 确认放置姿态 → 松开”。这仍是人工顺序联调，不是现有代码自动流程。
4. 最后测试运动中气路切换；确认夹爪动作冲击不会造成超调、掉线或误夹。若业务不需要运动中开合，可先在上层限制为到位后操作。
5. 每次增加负载或速度只改一个条件，复验最不利的机械臂姿态。记录达标的组合，而不是只记录单次成功。

发 4 后，须等 `state=HOLDING` 且实际误差稳定在约定容差内，再进行需要到位的气路动作。现有代码没有到位超时、夹紧成功判据或负载检测；没有传感器时只能采用人工确认和经实测的保守等待，不能声明已经检测到成功。

## 11. 故障与恢复验证

在机构和测试物有独立支撑、停机后不会跌落的台架上执行。故障注入先选择通信信号的可控断开，不把带载断电或拔插功率线作为常规测试方式。

| 测试 | 当前代码应有的行为 | 还要观察 |
| --- | --- | --- |
| GO 关闭时无 GO 反馈 | 腕部可正常标零、使能和运动 | 气路若已配置，可独立工作 |
| GO 启用后，任一受控电机已使能时掉线超过 100 ms | FAULT，全部电机失能，泵关、阀 OFF | 实物停机姿态、残压、掉线到实际停机的时间 |
| GO 已启用且报告非零错误，电机已使能 | FAULT，全部输出停止 | 原始错误码及驱动器故障原因 |
| 非法/越界目标 | 拒绝命令，返回 BAD_TARGET，不执行新轨迹 | 原有保持/运动/气路不会因此自动停止 |
| MOVING 中再次发姿态目标 | 返回 BUSY，原轨迹继续 | 不能把拒绝新目标当作停止 |
| 任意正常状态发 1 | 电机失能，泵关、阀 OFF | 正常停机保留零位，气路不自动恢复 |
| 电机失能时反馈丢失 | 已有零位失效；不主动关气路 | 此时气路异常需要显式停止 |
| MCU 重启/固件下载 | 电机初始失能，机构需重新标零 | 泵/阀整个启动时序；不会自动恢复夹持命令 |

FAULT 后反馈恢复不会自动重新使能。恢复流程：排除原因 → 支撑机构 → `command=1` 清故障 → 摆到约定零位 → `command=2` → `command=3`。重新使能后如需气路工作，再明确发送 5；不要让恢复动作默认继续夹持或取放。

| 常见表现 | 优先检查 |
| --- | --- |
| 打开 GO 开关后 `motion_ready=false` | GO KP 是否仍为 0，arm 比例是否为 0，行程是否仍 `{0,0}`，数值是否有限 |
| GO 不在线，腕部仍可用 | GO 控制是否关闭；ID、供电、RS485 A/B、UART7 波特率、PG1 方向、RX DMA/IDLE 回调 |
| GO Watch 命令写了又变化或不动 | 当前是否机构接管；enable/位置/速度/扭矩是否被应用层覆盖 |
| GO 方向或角度比例不对 | deg/rad、内部 6.33 是否重复换算、外部比例符号、是否改过驱动零位 |
| `air_ready=false` | 泵单引脚/推挽配置、OPEN/CLOSE 是否仍相同、掩码高四位、BUS 与引脚重叠 |
| 气路 `result=0` 但不动作 | 实物供电、功率驱动、气压、阀板协议、通道映射；软件没有动作反馈 |
| 接阀后 IMU/串口异常 | BUS1/2/3 引脚复用，main 的无条件 BUS1 初始化 |
| 泵启动时电机掉线/MCU 重启 | 供电压降、地线、感性负载保护、信号干扰；再检查真实机构负载变化 |
| GO 运动后腕部保持变差 | 新姿态下重力/惯性、管线阻力、M2006 饱和和跟踪误差 |
